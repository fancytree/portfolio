## PitchPro 主线

**挑战类型：** 信息与功能过于复杂（Overly complex information or features）。

**一句话版本：** 作为 Founding Product Designer，我把一次性 AI 排名需求重新组织成以 Project 为核心的持续工作区，让目标、人员、评估标准和后续动作在扩展与网页之间保持关联。

**业务背景：** ConnectNova 面向招聘和销售团队，支持从 LinkedIn 采集人员、按目标评估，并继续组织外联。Project 是保留目标和评估上下文的产品单位；平台的订阅转化、客户规模和收入效果尚无可核查资料。

**问题：** 列表排名结束后，用户仍需保存人员、保留选择理由、比较标准及下一步动作。用户成本是重复组织和切换上下文；业务侧待验证的成本是任务未完成和回访不足，不将其写成已测量的流失。

**两类问题证据：** 用户反馈/工作观察原件 + 任务完成或使用行为数据。两类均保留待补位置；当前只有既有项目稿的工作流描述和设计实物，不伪造访谈或实验。

**主要方法：** 信息架构（Information Architecture）与渐进式披露（Progressive Disclosure）。因为目标、人员、标准和详情分散，先定义持久的 Project 关系，再组织列表扫描与详情检查，不为装饰堆叠研究方法。

**策略：** 先确立 Project 上下文；使评估依据可见可改；让比较及后续动作沿用该上下文。

**过程：** 梳理重复的采集/组织/评估工作 → 定义 Project 模型 → 设计扩展、评估编辑与工作区 → 扩展 Campaign/Sequence 并通过共享组件落地。每步均对应现有稿件或本地产品证据。没有补写尚无实物的访谈、A/B 测试或被否定的产品模型。

### 优先补充的领先指标

1. 同一采集任务的完成率与成功保存率：___/___ → ___/___。
2. 从采集到首次有效评估的完成率和用时：___ → ___。
3. 评估标准的理解、修正和完成行为：___。
4. Project 再次打开/跨会话追加人员比例：___。
5. 找到并确认一个合适后续对象的任务完成率：___。

挑战中的主指标应在结果里使用同一定义闭环。没有改版前数据时，不把上线后使用率伪装成改版提升。

### 商业与规模字段

截至日期：___；注册用户：___；活跃用户/团队：___；招聘/销售用户构成：___；月度新增与增长：___；渠道/推广：___；付费转化：___；留存 cohort：___；Campaign 激活：___；外联回复与有效回复定义：___。

采集量、来源资料完整度、模型版本、用户渠道和 Campaign 受众会影响同期结果。只有存在实验或可比 cohort 时才估计设计净提升；否则写“同期观察到”，并说明限制。

### 定性反馈位置

角色：___；原话：___；日期和场景：___；对应的设计决策：___；是否允许匿名公开：___。不编造用户引语。

## Design Calibration Notes

- “AI re-rank 更高效” → Revise → 以 Project 保留目标、标准和人员解释设计价值，效率提升等待任务数据。
- “从一次性排名变为可复用工作区” → Keep → 原稿有明确个人提案和产品模型；补原始需求与备选方案以形成可追问证据。
- “三个导航层级变为两个” → Keep as structure → 用于解释架构变化，不等同减少任务点击数或时间的实测结果。
- “三种权重编辑方案” → Keep → 有设计稿支持，不追加未发生的用户测试。所选是视觉交互方向，最终权重校验另待证据。
- “用户控制带来信任提升” → Revise → 仅陈述标准可见可改，理解和信任的结论待反馈与行为验证。
- “Outreach / Sequence 仍是探索” → Revise → 本轮用户确认均已上线。架构稿与本地演示仍如实说明各自证据性质。
- “76%→93% 等结果已验证” → Remove from page → 用户明确来源待核对，数值仅留在本清单。
- “共享设计系统提升交付速度” → Revise → 保留变量/组件与跨界面一致性，不增加未经测量的提速比例。
- “AI 排名直接完成招聘决策” → Do not introduce → 页面描述人员评估与工作组织，没有把最终招聘判断交给模型，也不把分数解释为录用概率。
