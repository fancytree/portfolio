# JobNova 新案例：证据与数据补充表

页面：`/projects/jobnova-kit`。保留现有 Jobnova 页面及首页入口；新页为 noindex 草稿。正文沿用作品集英文，工作清单用中文。

## 叙事判断（PitchPro）

- **挑战类型：** 可用性问题（用户难以判断推荐、核查生成内容及掌握自动投递）。核心方法是用户旅程图（User Journey Map），访谈为问题发现的依据。
- **一句话版本：** 作为 Founding Designer，我把分散的求职步骤组织成解释、审核、授权、反馈的连续体验，定义 AI 何时提供判断依据、何时等待用户、以及执行后如何让结果可追踪。
- **业务背景：** 面向求职者的 AI 求职平台；匹配帮助选择机会，简历定制帮助准备材料，Auto Apply 与跟踪承担申请执行及后续管理。付费转化、留存和获客模式的具体数据尚缺，不推断商业模式效果。
- **两类问题证据：** 访谈反馈的既有归纳 + 历史使用漏斗。原始研究节选和数据导出仍需补充。上线漏斗不是改版前基线，不用它伪装前后对照。
- **用户成本：** 反复判断岗位、核查生成内容、操作提交及确认状态。**业务成本：** 设置或授权未完成会限制核心自动化的使用；是否影响付费或留存仍需数据验证。
- **策略：** 把扫描与解释分层；让生成内容可审核；把自动化拆成可理解的权限；执行结果回到申请记录。每项均由现有界面或录屏支持。
- **过程证据顺序：** 研究与旅程 → 工作流职责 → 三个关键交互决策 → 状态和系统 → 历史结果与下一步。

不虚构测试、A/B 实验、对照组、AI 架构、参与人数、引语或增长提升。用户在本轮确认身份为 Founding Designer，并授权暂用旧数据，稍后与开发同步更新。

## 每个设计决策补什么

| 设计决策 → 预期行为 | 领先指标（优先） | 证据位置与待补材料 |
| --- | --- | --- |
| 扫描列表 + 细节解释 → 更有依据地选岗位 | 解释查看率、详情到申请转化、决策用时、跳过率 | 04：已有界面；补用户任务、解释前后表现与失败例 |
| 变更概览 + 分节编辑 → 更快检查并纠正生成内容 | 生成到采用/导出完成率、编辑/还原率、任务用时、放弃率 | 05：已有录屏与界面；补一次真实错误及审核如何纠正 |
| 匹配/自主权/材料分组 → 理解权限并完成设置 | 设置分步完成率、权限理解、模式选择、规则修改/暂停率 | 06：已有设置稿；补原方案与改版、测量或测试 |
| 状态与申请记录 → 明确进展和下一步 | 未知状态反馈、失败恢复率、重复提交率、回访率 | 07/08：已有录屏及状态稿；补 QA 问题与恢复验证 |

不要把“高编辑率”直接解释为成功或失败；可能是积极审核，也可能是输出质量差，需要结合任务完成和用户反馈。不要把“无需批准”比例或提交成功率直接命名为信任。

```text

改动前：    改动后：

```

增长率为 `(本期 - 上期) / 上期`；零基线不报百分比。没有实验或可比 cohort 时写“同期观察到”，不写设计“带来”某个净增长。只有能分离外部变量时才提供设计净提升估计。

## Design Calibration Notes

- “更多申请创造更多机会” → Revise → 主叙事改为相关机会与可审核执行；申请总量本身不能证明求职质量。
- “分数使用户相信推荐” → Revise → 分数用于扫描，细节用于判断；不把匹配分数说成录用概率。
- “AI 简历自动完成” → Revise → 生成、审核、编辑分开；可编辑性由界面支持，节时效果待测。
- “Auto Apply 是开关” → Revise → 用匹配范围、材料和批准模式解释权限边界，不声称进行了尚无记录的实验。
- “状态透明带来信任增长” → Revise → 陈述已设计的状态与恢复入口，信任结论等待行为与反馈双重证据。
- “增长来自设计” → Remove → 目前没有设计前后对照或渠道控制，不提供净归因。
- “37% → 82% 证明用户放权” → Remove from new page → 现阶段缺 cohort、默认值与来源；放入台账等待核对。
- “75% 简历被 ATS 拒绝、早投 3× 回调” → Remove → 既有项目稿缺可核查来源，也无法证明本项目问题规模。
- 个人职责 → Keep → 用户已确认 Founding Designer；研究、交互、系统、QA 范围来自既有项目记录。未将本人写为 ML 架构或后端实现负责人。

## 招聘方视角完成度

- 已有：业务语境、个人角色、AI 与人的职责、具体界面、材料审核、权限设计、状态/恢复、共享系统、历史使用规模。
